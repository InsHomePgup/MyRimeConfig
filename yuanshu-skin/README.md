# 元书键盘皮肤 MyRime

iOS 元书输入法的键盘皮肤，配合本仓库的简体自然码双拼使用。皮肤文件全部由 `build.py` 生成，**不要手改生成出来的 YAML**，改 `build.py` 再重新生成。

这份文档写给下次迭代皮肤的人（包括新开的 Claude 会话）：先读完「设计目标」和「元书的坑」，再动代码。

## 设计目标

用户的要求，按优先级：

1. **手感好、不误触**。这是做这个皮肤的起因：元书自带的 default 皮肤给 `a` 上划绑了中英切换、空格上划绑了次选上屏，手指一拖就出错。
   - 字母键**不绑任何划动**，也**不加按下动画**。唯一保留的划动是逗号键上划出句号（微信也这样）。
   - 点击区域铺满整个格子，键与键之间的缝隙也算。看得见的键帽只是格子里缩进去的一块（背景样式的 `insets`）。
   - 第三行两端（Shift / 删除 / 符号 / 123）和第二行两端（A / L）的点击区域延伸到屏幕边缘，键帽用 `bounds` 靠外侧画。
2. **布局、行为对齐微信输入法**（iOS 版）。用户提供过微信各个界面的截图作为参照，截图不在仓库里；要对齐新界面时，先请用户截图，不要凭印象猜。
3. **外观跟 iOS 26/27 原生键盘一致**（液态玻璃）：
   - 键盘区背景几乎全透明（`#FFFFFF03`），透出系统的玻璃容器。画不透明背景会和系统容器的圆弧顶边出现接缝。
   - 浅色：所有键都是白色，没有底边，只有一道细阴影。深色：半透明浅灰。
   - 强调色是系统蓝 `#007AFF`，只用在发送类回车、返回键上。中英键的“英”保持黑色，用户不要彩色。
   - 候选栏不显示序号，首选不变色。
4. 先把 **iPhone 竖屏**做好。横屏和 iPad 暂时沿用竖屏布局（不配置的话会是空白键盘），是后续的待办。

**明确不做的**：

- **Emoji 面板**：元书内置的 Emoji 面板图标发糊，用户改用 iOS 自带的 Emoji 键盘（长按地球键）。皮肤里不要再加 Emoji 键，也不要切到 `emojis` 键盘。
- **字体**：键盘字体在元书 App 的「键盘字体」里设置，皮肤不打包字体（试过打包 Maple Mono + MiSans，不起作用，还让皮肤包多了 8MB）。
- **虎码专用的键**（比如反查）：现在只针对简体双拼，见仓库根目录 `CLAUDE.md` 的「改动范围」。

## 文件和流程

| 文件 | 作用 |
| --- | --- |
| `build.py` | 生成皮肤，生成前会自动检查（见下文）；只用标准库 |
| `demo.py` | 把键盘画成示意图，左浅色右深色；需要 Pillow |
| `build/`（不提交） | 生成结果：`MyRime/` 皮肤目录、`MyRime.cskin` 皮肤包、`preview-*.png` 预览图 |

```bash
python3 yuanshu-skin/build.py      # 生成 + 检查
python3 yuanshu-skin/demo.py       # 画预览图到 yuanshu-skin/build/preview-<键盘>.png
python3 deploy-yuanshu.py <手机地址> --skin --no-userdb   # 同步 Rime 配置并上传皮肤
```

- 只想传皮肤、不动 Rime 配置时，可以直接调 `deploy-yuanshu.py` 里的 `sync_skin(FileBrowser(地址), False)`。
- 上传后要在元书「键盘皮肤」里**重新点一下 MyRime** 才会加载。**不需要**重新部署 Rime。
- 元书的 WiFi 传输过一会儿就会自动关闭，连接被拒绝时请用户重新打开。手机地址会变，要问用户。
- 上传只会覆盖文件，不会删除手机上多出来的文件。删掉某个键盘或资源后，要用 File Browser 的 `DELETE /api/resources/Skins/MyRime/<路径>` 手动删。
- 预览图只是近似：按 393pt 宽画，SF Symbols 用相近的字符代替。它适合检查布局和颜色，最终效果以真机为准。改完先看预览图，再上传。

## 键盘和跳转关系

```
拼音键盘 pinyinPortrait（26 键，中英共用一套，中英键切 RIME 的 ascii_mode）
 ├─ 123 ─────────→ 主符号页 symbolicPortrait（数字行 + 常用中文标点）
 │                   ├─ 符号 ──→ 更多符号「常用」symbolCommonPortrait
 │                   │            └─ 底部分类栏：常用 / 中 / 英 / 括号 / 货币 / 数学 / 序号
 │                   │               每个分类是一个自定义键盘 symbol<Name>Portrait；左下 123 回主符号页
 │                   └─ 12/34 ─→ 九宫格数字键盘 numericPortrait
 │                                └─ 符号 → 主符号页
 └─ 各键盘左下角的蓝色 ← 都是 returnPrimaryKeyboard，回拼音键盘
```

- 拼音键盘底行：`123` / `，`（上划 `。`）/ 空格（显示方案名）/ 中英 / 回车。
- 九宫格数字键盘按**列**排：左列 `@ % -` 和 ←，中间 3×4 数字，右列删除 / 空格 / 换行（换行占两格高，同 iOS 数字键盘）。其他键盘都按行排。
- 工具栏（拼音键盘）：方案切换 / 常用语 / 剪贴板 / 收起。数字和符号键盘的工具栏是一排快捷符号加 ×。
- 「更多符号」只有第一页「常用」照微信截图做了；中、英、括号、货币、数学、序号的内容是自拟的常用符号，还没和微信对齐。

## build.py 的结构

从上到下：

1. **配色** `COLORS`：`light` / `dark` 两套，`ACCENT` 是强调色。`preview_glass` 只给预览图用，模拟系统玻璃。
2. **尺寸**：键盘各区高度、键帽缩进 `KEY_INSETS`、圆角、字号等，单位是 pt。
3. **`Sheet` 类**：一个键盘文件。`add()` 往根节点放一个样式，重名但内容不同会报错。常用的方法：
   - `bg(kind)`：背景样式，`kind` 是 `key`（字母键）、`func`（功能键）或 `accent`（强调色）
   - `text()` / `icon()`：文字或 SF Symbols 前景
   - `letter()`：字母键，带大写和按键气泡
   - `symbol_key()`：直接上屏一个符号的键，用的是 `{symbol: x}`，不经过 RIME
   - `func_key()`：通用按键
   - `backspace()` / `enter()`：删除键、回车键；回车按 `$returnKeyType` 显示 ↵ 或蓝底文字
   - `candidates()`：横向和纵向候选栏
   - `frame()`：把工具栏、按键区、候选栏组装成完整的键盘文件
4. **`EDGE_CELL` / `EDGE_VISUAL` / `edge_bounds()`**：第三行两端功能键的格子宽度和键帽宽度，所有键盘共用。不要在某个键盘里单独写死这几个键的宽度，否则会对不上。之前就出过不同界面删除键不一样宽的问题。
5. **每个键盘一个函数**：`pinyin_keyboard`、`numeric_keyboard`、`symbolic_keyboard`、`symbol_page(index)`。返回的是根节点字典。
6. **`SYMBOL_BAR`**（符号页顶部的快捷符号）和 **`SYMBOL_PAGES`**（更多符号的分类：键盘名、分类栏标签、是否图标、符号列表）。改符号内容只动这两处。每页的符号按 10 + 10 + 剩下的排三行；第三行按实际个数均分 123 和删除之间的宽度。
7. **`KEYBOARDS`**：键盘类型 → (文件名, 生成函数)。`config_yaml()` 据此写 `config.yaml`。
8. **`check_sheet()`**：生成后的自动检查，见下一节。
9. **`build()`**：生成、检查、写文件、打 `.cskin` 包。

常见改动：

- **换颜色、改尺寸**：改文件开头的常量。
- **改某个符号页的内容**：改 `SYMBOL_PAGES` / `SYMBOL_BAR`。
- **加一个新键盘**：写生成函数，加进 `KEYBOARDS`，然后在某个键上用 `{"keyboardType": "<名字>"}` 切过去。自定义的键盘类型名必须在 `config.yaml` 里声明，`KEYBOARDS` 会自动处理；检查也会拦住切到未声明键盘的动作。

## 自动检查

`build()` 会对每个键盘（浅色、深色）跑 `check_sheet()`，有问题就报错退出，不会写出半成品。检查这几项：

- 布局：同级不能混用 HStack / VStack / Cell；Cell 不能直接放在根上（元书会报错并放弃这一层）。
- 引用：每个 Cell、style、背景和前景样式、气泡、通知都必须有定义。
- 切换键盘：`keyboardType` 的目标必须是已声明的键盘。
- 按键区尺寸：同一行里全部写了宽度的，合计必须是 1；有自动宽度的格子时，固定宽度合计必须小于 1。列里的高度同理。

## 元书的坑

**已经在真机上确认的：**

- 元书「工具栏设置」里开了**「启用自定义工具栏」**时，会盖掉皮肤自带的工具栏。用户目前开着它，键盘上显示的是 ⌘ 和 ∨。
- **Shift 单击后一直保持大写**：是元书「键盘设置 → Shift 状态锁定」造成的，皮肤控制不了。
- 键盘区背景必须**几乎全透明**，不透明会和系统玻璃容器的圆弧顶边出现接缝。官方 default 皮肤也是用 `#ffffff03`。
- 某一行里放了**空白占位格**，看起来就是那一行右侧留了空隙。现在第三行按实际符号个数均分，没有空白格了。
- 文本样式会去掉首尾空白，要做两行文字（比如 `12/34`），就用两个前景叠起来，各自用 `center` 定位。
- 按列排（根上一个 HStack，里面放 VStack 列，列里的 Cell 用 `size.height`）可以正常显示。

**照文档或经验做的，没有专门验证过：**

- `config.yaml` 用的是旧写法 `iPhone` / `iPad`（文档说新版改成 `phone` / `pad`，旧写法仍兼容），这样也能兼容旧版元书。
- 自动宽度（不写 `size.width`）文档说会平分剩余空间。有一次右侧出现空隙，起初怀疑是这个原因，后来查明是空白格造成的。稳妥起见，除了空格这种一行只有一个的格子，都写明宽度。
- 中英键的“中 / 英”大小字，靠条件样式 `rime$ascii_mode` 加 `optionChanged` 通知来切换；空格上的方案名靠 `schemaChanged` 通知刷新。

**资料：**

- 元书 v3 文档：https://ihsiao.com/apps/hamster/v3/docs/ ，皮肤部分在「键盘皮肤」下。最全的是「配置项索引（全部 Key）」那一页。
- 文档源码：https://github.com/imfuxiao/Hamster3Document （`src/content/docs/guides/skins/`），可以 clone 下来 grep。
- 手机上的官方 default 皮肤（`Skins/default/`）是很好的参照，可以通过 WiFi 传输下载下来看生成出来的 YAML。
